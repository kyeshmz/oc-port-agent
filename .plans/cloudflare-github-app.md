# GitHub App with embedded OpenCode on Cloudflare

## Goal
Build a deployable, self-hostable GitHub App backend: Cloudflare scheduling/webhooks, durable per-target jobs, OpenCode Workerd SDK agents, isolated Linux verification, and host-controlled draft PR publication. Luna max implements/tests; Sol high independently reviews and Luna repairs findings. Deployment, app registration, credentials, and remote publication remain operator opt-ins.

## Conventions in force
- Preserve all pre-existing working-tree changes, including the public-repository harness. The unrelated `.plans/public-repository-tests.md` is not this task's plan; do not edit it.
- Implement a separate TypeScript ESM package at `apps/cloudflare/`; keep the existing CLI and its package/lockfile untouched except an additive README link in Phase 4. Use strict types and real installed package APIs, not guessed SDK signatures or unsafe type coercions.
- Consult OpenCode V2 docs only: https://opencode.ai/v2/docs/build/sdk/cloudflare/, https://opencode.ai/v2/docs/build/sdk/, and https://opencode.ai/v2/docs/build/plugins. Load relevant Workers, Durable Objects, sandbox-next, and wrangler skills. Context7 is now available through Code Mode; use it for current SDK/cloud documentation alongside primary docs and installed declarations, and do not substitute V1 OpenCode docs.
- Pin actual dependency versions and commit an app-local lockfile. New Workers use compatibility date 2026-10-09, nodejs_compat, logs and traces. Generate Env bindings with Wrangler and separate secret declarations when needed.
- Never deploy, create/register a remote GitHub App, push, create a remote PR, change credentials/global config, extract saved keys, or make paid model calls without separate explicit authorization. Local dependency installation, container builds, mocked HTTP, and isolated local tests are authorized.
- GitHub App private keys/tokens and model credentials stay in trusted Worker/DO bindings. Never give them to model tools, sandbox environment/files, reports, or logs. Authenticate webhooks over exact bounded raw bytes; authenticate admin routes; avoid arbitrary outbound URLs.
- Only target repository configuration approved by an authenticated operator is trusted executable policy. Upstream code/messages/instructions remain inert selected reference data. Do not load target/upstream plugins, agents, or instructions into the SDK automatically.
- Enforce safe paths, scope/protected/sensitive paths, content/response/time/attempt/step/job bounds, complete decisions and actual edits. No shell/network/Git/publish tools for the agent; trusted host verification uses argv and isolated job workspaces. Independently inspect outputs before publication.
- Persist durable transitions before external effects; deduplicate webhook/queue deliveries and jobs. Separate lastCheckedCommit from lastSyncedCommit; only a verified merge into the configured target base (or observing the committed checkpoint on that base) activates a checkpoint. No automatic merging or force pushes.
- Implementers may modify only owned files plus their automated checkboxes and appended execution log entries in this plan. Report honest test results with a handoff envelope; do not commit.
