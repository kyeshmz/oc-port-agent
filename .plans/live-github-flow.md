## Goal
Create one private disposable repository under `kyeshmz`, install a narrowly scoped GitHub App, and exercise the real deployed backend through discovery, agent adaptation, trusted verification, draft PR, explicit test-repo merge, checkpoint activation, and unchanged-upstream no-op.

## Conventions in force
- Preserve all prior CLI/App/smoke work and unrelated plans. `.plans/cloudflare-github-app.md` records prior implementation; this is a separate live-validation task, not a resumption of its source implementation phases.
- User explicitly authorizes creating the new test repository, adding the App, and verifying flows. Scope remote writes to that new repository and new dedicated live-test backend resources; do not alter existing repositories, the deployed SDK smoke Worker, account billing, or global authentication.
- Make the new repository private unless the user requests otherwise. Use distinct target `main` and reference `upstream` branches in this one repository so a single selected-repository installation suffices.
- Use least-privilege App permissions: contents and pull requests write, metadata read; no all-repository installation, auto-merge, force-push, or secret exposure. Merge only a verified disposable test PR as an explicit operator test action, never automatic application behavior.
- No raw credentials in chat, tool output, arguments, commits, evidence, or model/sandbox context. Existing gh and Wrangler authentication may be used without token extraction. Missing App/provider secrets must be entered by the user through a secure local/Worker secret path, not pasted into chat.
- Retain actual model/source/test/PR/merge/checkpoint evidence. PAT/CLI publication is not equivalent to installing/testing a GitHub App; do not substitute one and claim the App flow passed.
- Honor the user's preference for live Worker tests without local Docker. Any need for optional Linux verification/image deployment must be explained and authorized rather than silently replaced with a mocked result.

## Phase 3 — live flow assertions
- Signed real GitHub installation/repository webhook accepted; replay cannot duplicate durable work.
- Authenticated registration validates installation access to target/reference and explicit baseline.
- Reference change discovered with pinned before/after context and narrow target edit scope.
- Real SDK agent produces a scoped implementation edit; trusted unchanged tests pass; fixed helper/tests/config remain unchanged.
- App installation token creates one draft PR; unrelated/publication credentials never enter model/runtime verification workspace.
- Repeated run while PR open reconciles existing work and does not create duplicates or unnecessary model calls.
- Explicitly merge the verified test PR; real merged event triggers reconciliation; only confirmed base content activates lastSyncedCommit.
- Final unchanged-upstream run is model-free and produces no new PR.
- Save evidence and have Sol high independently review actual outcomes if delegated; clearly report any incomplete stage rather than claiming end-to-end success.

## Halt surfaces
Missing GitHub browser approval, App/provider secrets, Cloudflare plan/runtime access, ambiguous installation permissions, failed trusted verification, or publication/merge mismatch: preserve repo/evidence and ask for the exact missing step. Do not use personal-token bot writes as a replacement for the App identity.

## Out of scope
Existing production repository changes, all-repository App access, account/plan upgrades, raw credential extraction, npm publication, rewriting prior implementation, or claiming provider-backed/live PR success before it occurs.

## Definition of done
All live assertions pass on the new private fixture with verifiable GitHub/Worker evidence, or the repo/fixture is prepared and the exact user-required setup blockers are explicitly reported.
